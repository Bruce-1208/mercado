# SKU 白底主图缺失排查与修复

## 实际数据（只读核查）

共 106 个 AI 原创商品：66 个 completed、6 个 failed、31 个 pending、3 个 processing。
65 个 completed 商品缺少 SKU 白底图；它们的原始 SKU 快照也没有图片来源。
没有将商品总主图复制到各 SKU，也没有批量改写现有商品。
通过普通 HTTP 访问样本 1688 详情返回站点验证跳转，未获得可补采的 SKU 数据。

## 根因及修复

1. 采集只读取 skuItems 上的直接图片字段，漏掉规格选项图片和规格表图片。新增按明确规格值或 SKU 编号匹配；遇到冲突不猜测。
2. 已完成商品重新采集时，SQL 保留整份旧快照，导致新图片丢失。现在补入缺失 SKU 图片和图库，保留已有文案、类目、净收益、采购资料，并递增编辑版本。
3. 白底处理只读取映射后的变体。现在能按 supplier SKU 编号找回采集原图，不依赖数组位置。
4. 页面将缺原图统一提示为生成失败。现在区分缺少采集原图与待处理白底图；仅缺图的已完成商品显示待补充，仍禁止上架。

## 验证

聚焦回归 78 项通过，前端 Node 测试 54 项通过，Python / JavaScript 语法检查通过。
覆盖不同颜色对应图片、同色不同尺寸共享图片、图片冲突不猜测、补采已完成商品保留文案/类目/收益、按 SKU 身份补回图片、图片编辑与上架拦截。

扩大回归并非全绿：采购数据测试有 7 个测试夹具缺少 organization_key 或 mercado_store_site_settings 的失败；扩展通用测试另有 7 个列表静态断言、重量价格/权限/凭证相关失败。没有为绕过这些失败修改业务权限或无关代码。

## 使用

插件包：../zeshun-collector-extension-1.8.69-sku-images.zip（包含本工作区同时进行的 1.8.69 列表采集修复）。
更新插件并刷新 1688 详情页，补采原商品，然后选择商品执行 AI 任务生成 SKU 白底图。
服务端 Python 修改需要重启后加载；本次未重启正在运行的服务、未发布商品。
