# 账户支付管理

入口：工作台侧栏「系统管理 → 支付管理」，页面地址 `/billing`。页面包含「账户订阅」与「业务员打印余额」两个栏目；打印余额可以通过 `/billing?section=print-wallet` 直接打开，旧 `/print-wallet` 地址会自动跳转。

打印余额、充值和逐单打印明细统一在支付管理查看，订阅费用与打印余额分别记账。打印明细显示订单号、店铺/站点、打印时间、打印人员、扣费金额、剩余余额及生成/退款结果，支持订单号、日期、打印人员和流水类型筛选及分页。打印时间指系统成功生成面单 PDF 的时间，无法自动确认实体打印机是否完成打印；历史缺失完成时间的记录明确提示使用结算时间。

- 个人版 299 元/月，默认 10 个站点，管理员可调整至超过 10 个站点，月费不变。
- 企业版 599 元/月包含 30 个站点，核定的计费站点数超出 30 时，每站每月增加 10 元。例如 35 站点为 649 元/月。
- 计费主体是单个账户，不是企业下所有业务员共享。只有超级管理员可以查看全部账户和登记、调整订阅；其他账户只能查看自己的订阅和记录。
- 「登记充值」记录实收金额、月数、备注及操作人，并同步延长有效期。自然月续期，未到期从原到期时间起算，过期从当前北京时间起算；目标月没有对应日期时取月底。可登记优惠金额，需备注原因；不会自动扣款。
- 「调整」修改套餐、计费站点数和到期时间，留空到期时间表示未开通。修改前后均保留历史；调整不是收款，不产生收入。充值和调整记录不删除，最近 500 条在页面展示。
- 已分配站点来自美客多 `mercado_store_site_settings`，按账户企业及业务员显示名匹配，每个店铺的国家站点单独计数。停用店铺仍计入；其他平台当前须人工核定计费站点数。沿用现有按业务员名称关联的模型，同企业重名业务员须先改名以避免统计歧义。
- 已分配站点超过核定额度（个人版至少 10、企业版至少 30），账户业务请求返回 402。管理员保存套餐时也校验当前站点用量，不允许将额度降至用量以下。

## 启用与存储

服务端与 API 客户端须同步更新并重启。首次访问自动建立 `workbench_subscriptions` 和 `workbench_billing_records` 两张 MySQL 表，不修改既有账户、订单或店铺表。需要现有账户和美客多店铺配置表，以及建表权限。

**启用后既有普通账户也必须有有效订阅。** 上线前安排超级管理员录入实际有效期；没有记录的账户显示「未开通」，可登录并访问自己的订阅页面，但不能使用受登录/权限保护的业务功能。超级管理员免订阅，始终可以录入和纠正。此变更不主动终止已经启动的后台任务，也不替代内部服务令牌鉴权。

门禁覆盖工作台登录保护路由、业务 API 权限检查、浏览器扩展、AI 核重核价授权和服务端本机执行凭证验证。到期检查按请求执行，同一请求内缓存；数据服务故障返回 503，不默认为已付费。

API 模式通过受内部令牌保护的 `/api/db/workbench/billing` 访问服务端。数据库再次查询操作人的状态及角色，防止仅依赖浏览器传入权限。事务内锁定账户行；版本号防止覆盖他人修改；请求编号防止重复提交重复续期。金额以整数分存储。
