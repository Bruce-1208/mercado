# 统一订单管理

订单管理默认显示美客多和 Yandex。来源、国家、店铺、日期、状态筛选及分页均在同一个数据库查询中完成。

- Yandex 店铺使用负数店铺编号，订单主键为 `yandex:<campaign_id>:<order_id>`；页面显示平台原始订单号。
- 同步仅更新平台字段，保留采购、备注和人工流程状态。取消、交付等平台最终状态沿用现有工作流规则。
- Yandex 中央授权默认属于 `wuhan-zeshun`，可通过既有 `AI_ORIGINAL_YANDEX_ORGANIZATION` 配置企业。只看本人美客多店铺的账号不会因此获得 Yandex 权限。
- Yandex 费用尚未核实的订单不纳入利润合计，并在列表、详情及汇总中标注待核实。原币买家支付金额保留；缺少汇率时不伪造美元金额。
- Yandex 面单、拆包等平台操作继续在 Yandex 控制台完成，不发送到美客多接口。

## 同步

页面不再提供“拉取 Yandex 全部订单”按钮，新订单由后台自动读取，无需保持页面打开。维护时可运行 `python3 -m bit.yandex_order_sync` 对全部授权 Yandex 店铺进行历史回填。每段最多 30 天，使用 `nextPageToken` 取完所有分页，空时间段不提前终止。默认历史起点为 2000-01-01；`YANDEX_ORDER_HISTORY_START` 可以显式缩小范围。已有行按平台订单主键幂等更新。进度保存在 `.data/yandex-unified-order-sync.json`；异常不标记为完成。

后台工作进程每 15 分钟同步最近 30 天及更早尚未完结的 Yandex 订单。`YANDEX_ORDER_SYNC_DISABLED=1` 禁用该调度。失效或删除的中央授权将在下次同步更新统一列表的可见店铺范围。

美客多订单的“标价”保存官方 API 返回的卖家运费及币种，不再用商品重量和费率表估算。未发货时“实际运费”留空；确认发货后重新读取 Shipment Costs，保留发货前的 API 标价用于差额比较。发货前的缓存或读取失败不会填入实际运费；官方明确返回的零运费视为有效值。合包运费只在子订单间分摊 API 总额，不重新计算运费。

历史重量表标价在读取时隐藏，后台使用已缓存的官方 API 运费补全，缺少 API 数据时显示“待同步”。订单详情内独立的重量表查询工具只供参考。

## 验证

```sh
BIT_BACKGROUND_SERVICES_DISABLED=1 python3 -m pytest \
  tests/test_yandex_unified_orders.py \
  tests/test_yandex_unified_order_routes.py \
  tests/test_yandex_unified_orders_browser.py -q
```

路由测试导入工作台时需要本机 MySQL，浏览器测试需要 Playwright Chromium。

Yandex 订单主图通过商品目录补齐，订单列表与详情展示原价（买家商品付款）、积分及两者合计，全部保留原币。积分缺失或币种不一致时不生成合计。Yandex 不换算美元，不纳入美元订单金额汇总。


## 转运仓与仓库人员权限

新增或修改采购单可选择沙湖仓库、东莞仓、义乌仓，默认沙湖仓库。转运仓保存在订单的 `transfer_warehouse` 字段中，重新同步平台订单时保留，修改记录写入采购单操作日志。批量选择不同仓库的订单时，需要明确选择本次应用的转运商。

管理员在「人员与权限」编辑仓库人员账号时必须选择「绑定仓库」，保存在 `warehouse_key` 字段中。未绑定的原有仓库账号暂不能访问订单，需按实际仓库配置，不自动推定人员所属仓库。仓库人员的订单列表、状态数量、详情、物流、打印和打印明细仅限绑定仓库，并继续遵守企业和店铺权限；仓库人员不能更换订单的转运商。批量修改在事务内校验仓库，整批发现越权时回滚。

服务启动时补齐人员仓库字段；订单表初始化时新增转运仓字段，历史和新同步订单默认沙湖仓库。中心服务及工作台客户端须同时更新，重启后刷新页面。
