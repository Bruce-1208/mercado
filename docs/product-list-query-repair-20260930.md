# 产品列表查询卡住排查与修复

## 现场证据

2026-09-30 对当前配置数据库执行只读查询。产品总数为 1,616,592。

- 原明细 SQL 的 EXPLAIN：产品表 `ALL`，估算扫描 1,088,723 行，`Using temporary; Using filesort`；关联运营分类使用 hash join。
- 原查询每页 500 条，在 10 秒 socket 读取期限内未完成，10,114 ms 返回 MySQL 2013。
- 单独按主键倒序取 100 条 id/title 为 3 ms，仅用于定位排序/关联问题，不是完整列表性能对比。
- 修改为先筛选分页再关联后，完整 500 条列表单次耗时 392 ms：连接 0.8 ms、计数 320.5 ms、明细 44.0 ms、转换 25.6 ms。
- 修改后 EXPLAIN：产品表主键倒序 index scan，分页派生表 500 行；外层排序仅针对本页。

以上为同一数据库的单次采样，可能受缓存影响，不代表线上延迟分位数。性能采样跳过建表/迁移入口，未执行 DDL；不包括首次 schema 检查、鉴权、HTTP 传输和浏览器渲染。

## 修改内容

1. `erp/mercadolibre_collection_store.py`：将筛选、排序、LIMIT/OFFSET 放在派生表内部，再关联分类和采集信息，维持计数及筛选语义。计数和明细 SELECT 设置 MySQL 8 秒执行期限；列表连接使用连接 3 秒、读取 10 秒、写入 5 秒期限，不改变后台写入任务的连接配置。
2. 记录 `mercado_list_query` 日志，含 connect/schema/count/page/decode/commit 阶段耗时、分页参数和总耗时；失败或超过 2 秒使用 WARNING。日志不记录搜索内容、产品内容或凭据。
3. 浏览器单次请求 30 秒超时，覆盖响应体读取；临时网络错误及指定暂时性 HTTP 错误延迟 1 秒自动重试一次。失败后展示“重新加载”；权限或业务错误不自动重试。新请求取消前一次请求及其重试等待，迟到结果不能覆盖新列表。加载时清空过期选择和行数据。
4. 远程数据库列表调用使用 3 秒连接、25 秒读取期限，仅请求一次，避免与浏览器叠加重试。
5. 补齐远程客户端 `weight_status` 参数及内部产品列表转发；去掉内部产品列表误传的 `filter_token_ids`（列表存储函数不接受该参数）。原 `token_ids` 权限范围保留。
