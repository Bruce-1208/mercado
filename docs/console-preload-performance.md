# ERP 全模块预加载与性能检查（2026-10-07）

本次给 39 个保留模块页面登记预加载策略。38 个当前侧栏可访问模块在桌面（1440 × 1000）和手机（390 × 844）均逐一完成首次进入、返回总览、重复进入检查；智赢采集内部保留页没有可用侧栏按钮，按权限策略跳过后台读取。独立导航页面通过浏览器文档预取处理。

## 机制与性能边界

- 页面原有 DOM、筛选和已选择数据保留。预加载仅安排登记过的同源读取接口和内嵌页面，统一预加载队列最多 2 路后台工作、同一时间最多 1 个内嵌页面，优先处理悬停和键盘聚焦的模块。
- 缓存保存在当前浏览器页面内，按企业作用域、请求参数和凭据区分；最多 64 项、合计 12 MiB、单项 3 MiB；任务状态快照 5 秒到期，列表与元数据 120 秒到期。用户首次读取消费预热响应，后续手动刷新重新读取服务端。
- 同一读取的并发请求共享网络响应；每个调用者可独立读取响应体。单个请求取消不会误取消其他调用者。写请求使预热响应失效，写入后读取不会复用写入前仍在途的结果。
- 隐藏浏览器页面暂停新后台工作；内嵌页轮询通过父模块实际可见状态暂停和恢复。任务执行、停止、批量变更、运费刷新及 Yandex 服务启动保留显式操作流程。
- 服务端仅对接受 gzip 的普通文本响应压缩，保留登录 HTML 和 API 的现有缓存策略。带版本参数的公共静态资源使用一天浏览器缓存及条件验证；流、范围请求、已编码数据和禁止转换的响应保留原有传输方式。

## 可复现的离线结果

审查使用真实 `index.html` 和本地静态脚本；所有 HTTP 请求都被截获为无业务数据的固定响应。内嵌文档替换为无脚本的最小页面，因此下面的耗时仅覆盖父控制台的页面解析、同步导航和布局，真实数据库、业务 API、公网以及内嵌页完整业务耗时需要在部署环境继续测量。

- 39 个模块登记覆盖通过；38 个可访问页面首次和重复进入均正确激活。
- 桌面和手机均无未捕获 JavaScript 错误、无控制台错误、无重复 DOM ID、无整页横向溢出。
- 首次导航发出的假接口/内嵌文档请求由 69 次变为 26 次，减少 62.3%；首次访问共命中 38 份预热 JSON，6 个内嵌页直接使用已载入文档。任务状态在逐模块访问过程中超过 5 秒有效期后重新读取，确保首次展示的新鲜度。
- 初始观察窗口由 10 次读取增加至 68 次读取，包含提前载入的模块数据、内嵌页和独立文档。后台预读把访问成本移到空闲时段，生产服务器总负载仍需根据模块使用频率测量。
- 初始后台阶段没有非读取请求。逐模块导航只捕获到 Yandex 页显式触发的 2 次服务启动 POST，所有请求都在离线测试中被截获。
- 优化后的主 HTML 为 1,956,233 字节，gzip 为 345,959 字节，减小 82.3%。这项数字只对应主 HTML，静态资源及 JSON 的压缩收益另计。
- 单次样本的 DOMContentLoaded 为桌面 272.4 ms、手机 193.6 ms。运行间波动明显，首屏加速比例需更多稳定样本。
