# 店铺链接后台任务恢复

店铺同步请求和各店铺完成状态保存在 MySQL。重启后，未完成的店铺扫描立即恢复调度；已经完成的店铺继续使用原有同步周期。同步期间新增的请求使用版本号保存，避免同一秒内的请求被完成状态清除。

批量后台修改和删除任务在启动前写入 SQLite 队列，每条链接处理后的结果单独提交。后台进程重启时使用原任务编号恢复进度，仅继续尚未记录结果的链接。单条已经返回并记录的失败或部分成功保留结果，供用户检查后重新提交。

默认队列文件为 `runtime_logs/store-link-remote-update.sqlite3`，可通过 `MERCADO_STORE_LINK_REMOTE_UPDATE_PATH` 指定绝对路径。该路径应在部署持久化目录中，重启和更新服务时保留队列文件及 SQLite 的 WAL 文件；同一服务器上的 Web 和后台进程必须使用相同路径。

服务端后台启动时调用 `start_store_link_remote_update_recovery()`；客户端不会运行此恢复线程。恢复调度由跨进程单例锁保护，链接写入继续与店铺同步共用原有任务锁。批量提交通过 SQLite 事务限制为一个未完成任务，多个进程同时提交也不会创建竞争任务。

如果进程在平台写入成功后、单条结果提交前退出，恢复时可能再次发送该链接的绝对目标值（售价、净收益、状态、重量和尺寸），不会叠加加价或扣款。删除任务先读取平台状态，已删除的链接只补写本地状态。店铺授权在恢复执行时重新读取，队列不保存 Access Token 或 Refresh Token。

Web 与后台服务分离部署时，重启 Web 服务不会停止后台执行；后台进程自身重启后，持久化队列恢复未完成工作。
