## 每 1,000 件估算

实际流程生成西班牙语和葡萄牙语内容，并可能额外调用分类、属性补全及规格翻译。以下是全部调用合计的情景预算，不是实际账单；假设每次请求输入均不超过 32K：

| 场景 | 每件累计输入 Token | 每件累计输出 Token | 1,000 件费用 |
| --- | ---: | ---: | ---: |
| 简单单次文案 | 1,000 | 500 | 0.60 元 |
| 双语文案及少量补全 | 5,000 | 2,000 | 2.60 元 |
| 多属性、多规格及额外补全 | 15,000 | 5,000 | 7.00 元 |

计算方式：1,000 ×（每件输入 × 0.2 + 每件输出 × 0.8）÷ 1,000,000。重复失败、长上下文和更多规格会增加成本；本地白底抠图无图片 API 费，电费和服务器成本不含在内。页面保留累计 Token 与费用估算，可在实际生成后按新增金额校准。

# 美客多商品生成：每款 0.03 元预算

美客多 AI 原创商品入口固定使用官方 `deepseek-flash`，关闭思考模式，图片使用本地抠白底。预算覆盖启用费用记录后的该商品所有文案、分类、属性、SKU 调用及重试。历史未记录调用、刊登阶段的其他服务、机器和电费不在此账本内；其他平台的生成设置不受影响。

## 使用方式

在 AI 原创工作台选择美客多商品并执行任务。工作台显示每款模型费用估算、待确认费用预留和剩余预算。首次生成后，重复提交会复用输入未变化的已完成步骤；实时分类规则仍会重新读取。修改商品或重新采集不会增加新的三分钱额度。

任务仅在保守闲时窗口开始付费调用：北京时间工作日 09:00–12:00、14:00–18:00 等待，其余时间可执行。未内置法定节假日日历，因此工作日节假日也保守等待。页面显示预计继续时间，服务需要保持运行；服务重启后需要重新提交，已保存费用和准备进度仍会读取。

复杂商品或预算不足时，系统保留草稿并提示人工补齐。费用不确定时需核对 DeepSeek 账单；普通重试不能清空账本或追加额度。若当前来源资料已足以完成任务，仍可复用已生成内容和人工补全的数据，不再产生模型费用。

## 减少调用

- 首次请求合并生成双语标题、简短详情和事实属性。移除提示词中的图片地址、价格、库存等无关字段，保留全部 SKU 身份和规格，不静默截断 SKU。
- 使用内置的 22 类常用品类词汇匹配美客多实时返回的候选项。词库不保存平台分类 ID；有歧义时继续模型判断或人工选择。
- 已翻译属性通过实时类目规则匹配，只对缺失必填属性补问；没有来源依据的值交由人工核实。
- SKU 以去重后的规格选项映射，价格、库存、图片和 SKU 标识保持原值。
- 已完成步骤按输入指纹复用；完整相同请求也有逐商品缓存。规则变化时重新校验，不沿用失效枚举 ID。

## 预算保护

计费使用 2026-10-03 核验的 [DeepSeek 官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)：Flash 闲时每百万 Token 缓存输入 0.02 元、未缓存输入 1 元、输出 4 元；高峰分别为 0.04、2、8 元。

每次调用前以输入 UTF-8 字节上界加协议余量估算输入 Token，以高峰未缓存价格预留输入和最大输出费用，并缩小允许的输出上限。预留必须先保存成功才能发起请求。请求返回后按供应商报告的 usage 和保守时段费率结算；跨越高峰边界时按高峰估算。因此估算值可能高于实际账单，超长输入也可能提前转人工。价格变化时需更新费率配置；此实现不读取实时账单。

SDK 自动重试关闭。超时、用量缺失、账本保存失败均停止后续付费调用；未知请求保留预留额度。进程崩溃留下的 pending 请求也不会自动重新付费。每款由 MySQL advisory lock 串行处理，拿锁后重新读取商品；费用版本以数据库行锁和比较更新校验，避免多个工作进程重复使用同一额度。重新采集和旧快照写回保留新账本。

账本保存在 `source_snapshot_json.ai_original.generation_budget`，包括费用版本、Token 用量、已计算费用、待确认预留和有限的结果缓存；不记录 API Key 或请求全文。
