# AI核重核价

本模块已接入泽顺控制台的商品管理导航和角色权限。提供商品任务、参数设置、异常编辑与重试、日志、全量/成功/异常 CSV；后台使用本机 SQLite，不采购 ERP、不依赖新的云数据库。

## 当前交付与实机接通条件

六个模块的执行代码、状态机、异常分支和后台线程已实现。首次运行仍需在已登录的真实网页上完成 DOM 字段适配：仓库现有智赢代码提供了商品卡片、标题、图片、翻页选择器，其余 SKU、聊天和保存字段没有可验证的页面样本，默认保持空白。**空白不是可用适配器；启动检查会阻止未配置流程。** 不应把模拟测试通过解释为智赢/1688实站验收完成。

任务页提供「打开 Edge 登录智赢」与「我已成功登录」。登录地址固定为 `https://meli.zying.net/#/login`，商品分类、采集、筛选与回填固定使用美客多版 `https://meli.zying.net/#/product`；按钮调用本机安装的 Edge，账号密码由人工在该窗口输入。确认按钮会检查后台登录状态，不能在登录页直接跳过。实际商家咨询和 ERP 写入仍需完成页面适配、模型配置及独立参考重量准备。

## 任务页操作顺序

1. 点击「打开 Edge 登录智赢」，在 Edge 窗口完成登录，再回控制台点击「我已成功登录」。
2. 读取分类列表后选择分类，或保持「全部分类 · 不筛选」。不筛选会清空页面已有分类条件。
3. 必须填写起始页、结束页，都是1–10000的整数，结束页不能小于起始页；所选页数不能超过配置的 `max_pages`。未确认登录或参数不合法时，启动按钮禁用，后端也会拒绝启动。
4. 点击「采集所选范围」，再点击「开始 / 继续处理所选范围」。例如第3–5页只采集这3页，前两页仅用于翻页定位，不会加入本次任务。
5. 分类、页码、商品列表地址共同决定本次范围。续跑只复用相同范围的检查点；换分类或页码不会误用旧进度。重复商品保留历史状态，同时记录其属于本次范围。后续处理不会执行其他范围的任务。

关闭或更换 Edge 会话后需要重新确认登录；更改连接地址或智赢列表地址也会清除确认状态。程序重启后保留上次分类和页码，`--run` 使用上次保存的范围，仍需原 Edge 会话有效。

默认 `reference_mode=erp`，以 ERP 原有重量为对照；`writeback_enabled=false`。如采用人工实测，将对照模式改为 `manual` 并填入 `measured_weight_g`。停用对照只允许提取和人工审核，不会自动通过重量校验。

## 启动

已有控制台依赖可直接使用。独立运行的最小依赖：

```powershell
python -m pip install -r erp/ai_weight_price/requirements.txt
python -m erp.ai_weight_price
```

浏览器打开 `http://127.0.0.1:5018/ai-weight-price`。此入口不需要 MySQL；仅监听本机回环地址。原泽顺控制台入口是 `http://127.0.0.1:5000` 的「AI核重核价」，需要登录并具有 `ai_weight_price.view` / `ai_weight_price.execute` 权限。远程公网控制台只显示本机入口，不会把操作默默移到服务器。

```powershell
# 仅首次配置 API 时，设置启动进程的环境变量；不要把真实密钥提交进 Git
$env:DASHSCOPE_API_KEY="在这里填入你自己的密钥"
python -m erp.ai_weight_price

# 配置完成后，自动恢复尚未完成的处理任务
python -m erp.ai_weight_price --run

# 自定义本地目录和端口
python -m erp.ai_weight_price --data-dir .\output\ai-weight-price --port 5018
```

macOS 使用同样的 Python 模块，环境变量用 `export DASHSCOPE_API_KEY=...`。也可使用环境变量 `AI_WEIGHT_PRICE_DATA_DIR` 指定本地数据目录。

集成控制台的启动方式沿用项目 README。打包规则原有 `collect_submodules('erp')` 和模板目录收集会包含新模块；本次未重新打包或部署公网控制台。

## Edge 登录会话

使用任务页按钮自动打开本机安装的 Edge，无需手动启动调试端口。模块在数据目录内使用 `edge-profile` 持久化配置，保留人工登录会话，不要求关闭日常 Edge 窗口。账户密码由人工在智赢页面输入；点击确认后，程序检查后台页面与登录状态，只保存确认时间和浏览器会话标识，不保存密码或导出登录凭证。

默认 CDP 地址是 `http://127.0.0.1:9222`，只接受本机回环地址。若此端口被其他浏览器占用，请在参数设置更换空闲端口，再点击登录按钮。Windows/macOS会自动寻找 Edge 的标准安装位置；自定义路径可通过 `AI_WEIGHT_PRICE_EDGE_EXECUTABLE` 指定。

停止任务只关闭程序创建的临时采集页，人工登录页保留。后续1688搜索和咨询也复用同一个 Edge 会话，请在该窗口中人工登录1688。

## 页面适配

在「参数设置 → 页面字段适配」配置 CSS 选择器；均针对实时 DOM，无网页 API 抓取。字段含义如下。

| 字段 | 要求 |
| --- | --- |
| `erp_rows` | 每件 ERP 商品的容器；默认 `.product-item` 来自已有智赢采集代码 |
| `erp_id` | 卡片中的 ERP 核心商品主键；必须确认不是外部平台 listing ID |
| `erp_title` / `erp_image` | 卡片中的标题、主图 img；默认 `.product-title` / `img.product-pic` |
| `erp_description` | 商品描述；未配置时保留商品卡片完整可见文本 |
| `erp_sku` | 明确目标颜色、尺寸、型号、包装数量的唯一 SKU 描述 |
| `erp_reference` | 独立参考重量，须带 g/克/kg/公斤/千克单位 |
| `erp_edit_link` | 编辑链接 `<a>`，使用实际 href，不猜测编辑地址 |
| `erp_next` | 仅匹配可用的下一页按钮；不可匹配禁用按钮 |
| `search_input` / `search_button` | 1688 搜索框与搜索按钮；逐字输入清洗后的标题，不拼接搜索 URL |
| `result_links` | 真实候选详情页链接；限制到 `detail.1688.com` |
| `supplier_title` / `supplier_image` / `supplier_description` | 详情页商品信息 |
| `supplier_merchant` / `supplier_merchant_attribute` | 商家身份元素及其稳定 ID 属性 |
| `sku_rows` / `sku_id_attribute` | 每一个可供货 SKU 行与稳定 ID 属性 |
| `sku_label` / `sku_price` | 每行目标规格和确定的人民币单件单价 |
| `chat_open` | 详情页客服入口。须能打开有独立、可恢复地址的网页会话 |
| `chat_identity` / `chat_identity_attribute` | 会话所属商家 ID；必须与货源商家一致，支持 iframe |
| `chat_input` / `chat_send` | 输入框与发送按钮 |
| `chat_messages` | **仅商家发来的入站消息**，排除本人消息、系统欢迎语、已读提示 |
| `chat_message_id_attribute` | 稳定且唯一的消息 ID |
| `chat_message_time_attribute` | Unix 秒或毫秒时间戳；用于排除旧消息及超过回复期限的消息 |
| `risk` | 可见验证码/风控弹层 CSS；另有操作频繁、发言受限等文本检测 |
| `erp_edit_id` / `erp_edit_sku` | 编辑页商品主键及 SKU；两项必须与任务完全一致 |
| `erp_cost_input` / `erp_weight_input` | 成本输入框（人民币）与包装重量框（克），必须唯一 |
| `erp_save` / `erp_saved` | 保存按钮与本次保存成功后才出现的提示；之后刷新回读数值 |

如果网站只提供桌面千牛协议、无可恢复网页会话、SKU 需要多级点选后才露出价格，或页面不提供消息 ID/时间戳，当前通用 DOM 适配器会标记异常，需要进一步编写该页面专用适配，不能随便填写近似选择器强行运行。

ERP 商品 ID 是任务主键。同一个父商品有多个变体且无法确定唯一 SKU 时，不应该任取最低价或任意变体。先把 ERP 任务定义到明确可编辑的目标 SKU，再开始匹配。

## 处理流程和恢复

1. 逐页采集，只插入新商品，重复采集不覆盖历史状态、人工修改和证据。逐页保存游标；中断后前序页仅翻页，不重复提取。已完整采集结束后，再采集会从第一页查找新商品。
2. 以清洗标题在1688页面逐字搜索，搜索前随机等待2–6秒，读取有限候选详情。只接受确定的SKU价格，范围价和促销/起批信息不能自动当成本。
3. 同款初筛与复核均比较主图、标题、描述、目标规格。两次必须认定同款、关键规格可确认、选择同一实际SKU，且分数严格大于配置门槛（至少0.95）。
4. 随机话术自动附上实际商品链接和SKU，明确问单件含包装总重。保存商家、会话、消息和发送前已有消息ID。先事务预占商家和限额，再点击发送。
5. 状态变为 `waiting_merchant_reply`；工作线程可以处理其他商品。默认每15分钟查一次，期限30分钟；即使期限短于轮询周期，到期也会检查。只有发送后的新入站消息才用于提取。
6. 模型只输出数字克重或 `null`。净重、整箱重、多个规格或重量范围等歧义应拒绝。原始回复与模型证据持久保存。
7. 根据独立对照校验重量。通过后且启用回写，定位编辑页核对商品ID及SKU，记录修改前数值，填写成本和克重并保存，刷新回读成功才进入 `success`。

`pending` / `waiting_merchant_reply` / `success` / `exception` 为四种业务状态，`stage` 记录内部执行位置。运行中关闭进程后，后续可继续已有队列；`send_reserved` 或 `writing` 阶段中断，因无法确认外部副作用，恢复时转为异常，交人工核对。手动重试已有会话只重新读回复，不再次向商家发送消息；商家永久去重记录不删除。修改目标 SKU 会使旧匹配证据和重量失效，需要重新匹配。

## 限流与熔断

- 每日默认25个商家咨询，按北京时间自然日；可调整当日硬上限。预占/结果不确定的发送也计入当日限额。
- 同一商家永久唯一，数据库唯一索引兜底；不同商品也不会再次咨询该商家。
- 两次咨询至少间隔60秒；配置只能提高间隔。
- 最多2个等待会话；配置可降低到1。
- 打字后再随机等待1–3秒点击发送；话术至少2条不同文本。
- 验证码、频繁操作、发言受限触发持久化熔断。停止本次处理，不自动重启；人工处理页面后才能解除。
- 达到日限额后暂停新咨询，已发送会话仍可轮询；其余任务设置为次日再尝试。进程保持运行时跨日继续，关闭后用「继续」或 `--run` 恢复。
- 跨进程锁避免同一数据目录被两个实例同时运行；数据库事务保证预占的原子性。多台电脑不要独立运行相同账号的咨询队列，否则各机 SQLite 的去重和限额不会共享。

随机延时不保证平台不会触发风控；这里只做节流和遇到限制停止，不绕过验证。

## 重量误差的含义

令 `w` 为商家回复提取的包装重量，`r` 为 ERP 原参考重量或人工实测重量：

```text
w <= 500g：abs(r - w) <= 50g
w >  500g：abs(r - w) <= 30g
```

阈值可收紧、不能在配置中突破50/30g。500g正好采用50g档。缺少 `r` 就无法计算误差；不允许拿 `w` 与自身比较后判通过。校验只是两个数值是否接近，不证明商家给出的重量等于真实实测值。

## API 与硬件选型（2026-09-06 核查）

建议先采用 **Qwen3-VL-Flash 初筛 + Qwen3-VL-Plus 复核**。两者支持视觉输入，适合商品图片与中文规格。没有在本公司的真实商品集上做过模型对比，因此不能承诺这是所有API中实测性价比最高、或任何模型固定达到95%准确率。

| 模型 | 每百万输入/输出Token，北京地域，输入≤32K | 用法 |
| --- | --- | --- |
| Qwen3-VL-Flash | ¥0.15 / ¥1.5 | 所有候选初筛、商家文本重量提取 |
| Qwen3-VL-Plus | ¥1 / ¥10 | 只复核初筛高分候选 |

官方实时价格和区域差异见 [百炼模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)。估算：每次候选输入6000、输出400Token，Flash约¥0.0015，Plus约¥0.01；每商品初筛5次+复核1次，则1000商品约¥17.5，另加少量重量提取成本。图像分辨率、实际Token量和候选数会改变账单，运行日志记录API返回的Token用量。相比一开始投入本地推理维护，这个规模先用API更便于评估。

| 设备 | 本地建议（需实测） |
| --- | --- |
| M5 MacBook Air 16GB | Qwen3-VL 4B 量化版先试；8B可做小上下文评测，留出浏览器和系统内存，Air持续负载性能需实测 |
| M4 Mac mini 16GB | 同样先4B；更适合固定放在办公室做低并发服务，8B需控制上下文与图片数 |
| RTX 4060 Ti，32GB系统内存 | 本机 `nvidia-smi` 实测8188MiB显存，即8GB版本。优先4B量化，8B模型权重加KV/视觉缓存可能挤满显存，不建议作为默认长上下文服务 |

[Ollama 官方模型库](https://ollama.com/library/qwen3-vl)的4B模型包约3.3GB、8B约6.1GB；包大小不是运行总内存。建议从4K–8K上下文、两张缩放图片、单推理并发开始。模型本身支持更长上下文，不代表16GB机器可以把最大上下文开满。

```bash
ollama pull qwen3-vl:4b
ollama serve
```

然后 API 基础地址填写 `http://127.0.0.1:11434/v1`，初筛/复核/提取模型均填写已安装模型名。接口格式参考 [Ollama 兼容API](https://docs.ollama.com/api/openai-compatibility)。同一个本地模型运行两遍并不相当于独立正确性保证，建议本地做初筛、暂以人工复核抽样为主，评测后再决定全本地。模型能力与部署参见 [Qwen3-VL 官方仓库](https://github.com/QwenLM/Qwen3-VL)。

### 如何验证“95%”

先标注200–500组真实商品/候选，包括外观近似但尺寸、颜色、材料、每包数量不同的困难负例。重点统计自动通过样本中的正确比例（precision）、错误放行数、拒绝率和每件成本，分品类评测。不要只检查模型自报 `confidence`。逐条人工复核试运行结果，确认商品与SKU、包装重量对照和ERP单位无误后再启用自动回写。
