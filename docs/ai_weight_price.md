# AI核重核价

本模块已接入泽顺控制台的商品管理导航和角色权限。提供商品任务、参数设置、异常编辑与重试、日志、执行批次 Excel 和全量/成功/异常 CSV；商品任务、批次、日志、运行状态、商家去重和模块配置统一存储在当前服务器 MySQL，不采购 ERP、不依赖新的云数据库。

## 当前流程（2026-09-07 更新）

默认 `workflow_mode=image_first`，每件商品依次执行：

1. 登录智赢产品列表并应用所选分类；可选填起始产品编号，程序从该编号（含）开始按页面当前顺序继续，达到本次最多商品数后停止。未填编号时从分类首件开始。每件商品先实时读取审核状态，只有“待审核”进入1688和AI流程，其他状态直接跳过。
2. 主图上传到1688首页，等待图片预览并点击“搜索图片”。浏览器使用可见 Edge，操作过程不使用无头模式；控制台只记录状态和日志，不展示或采集页面截图。
3. 默认读取搜索结果前10张候选图并全部评分；图片数量可在参数设置中调整（1–20）。只在明确判定为同款的图片中选择分数最高的一张；同款匹配分数**大于等于95%**即进入该1688商品明细，读取完整SKU价格和包装重量证据。
4. 不再用ERP资料匹配具体变体；以该同款1688链接中最高的最终人民币售价加 ¥5 作为计价依据。重量优先读取结构化包装信息，缺失时从最高价SKU标签中的显式 `kg/公斤/g/克/斤` 证据提取并换算为克；模型不能单独决定单位或数值。
5. `ceil((当前最高变体价 + 5元) ÷ 1美元兑换的人民币金额)` 回填“净收益（美元）”。重量以克回填“重量”字段；只要重量或净收益成功回填保存，审核状态在同一次保存中改为“通过”。保存后回读不一致表示外部写入结果未知，批次会暂停当前商品，要求人工核对后才能继续。
6. 没有超过门槛的匹配：记录本地状态 `blocked` 和原因，不修改重量或净收益，并把智赢审核状态改为“价格异常”。
7. 匹配成功但缺少重量：保留原重量，只回填净收益并把审核状态改为“通过”，本地状态仍记为 `risk`，用于提示重量证据不完整。不等待千牛回复。
8. 图片已匹配但SKU或最终成本无法确认，或搜索/识别没有得到可回填结果：保留原价格和重量，把审核状态改为“价格异常”，并记录本地风险结论与具体原因。保存失败或回读不一致时暂停，避免把同步失败记录成成功。
9. 成功、屏蔽、风险均计入本次数量。默认10件，达到上限不采集第11件。状态和数值使用同一次保存，并在重新打开商品后统一回读；数据库、日志、Excel分别记录修改前值、计划修改值、实际回读值。

图片确认同款后，程序不再匹配具体变体，而是读取最高分图片候选链接内的完整SKU矩阵，以其中最高的最终单价加 ¥5 作为计价依据计算并回填净收益；最高价SKU的结构化包装重量或标签重量可同时回填。任务详情会保留完整变体列表、最高价SKU和定价策略，便于审计；任何一个SKU价格缺失或格式无效时，不推测最高价，也不执行回写。

搜索超时属于未取得可回填结果：最多等待30秒，保留重量和净收益并把审核状态改为“价格异常”。遇到1688登录页、验证码或人机审核时，批次暂停且当前商品保持待处理；人工在可见 Edge 中完成处理后，打开控制台的“继续执行”开关，从当前商品重试。异常商品处理完成前不会读取下一件，可单条重试或人工跳过。

泽顺插件「核重核价」页提供登录、分类刷新、起止页、首个选中页的起始商品序号（默认1）、每次最多商品数以及启动/停止；泽顺控制台任务页保留状态、任务明细、参数设置、异常处理与批次Excel导出。状态和日志每2秒刷新。`writeback_enabled` 控制自动核重核价的数值与审核状态回写；关闭时只记录本地结论。任务详情的“人工核验”可在手动填写重量和净收益后直接同步智赢，保存成功后审核状态同样改为“通过”。

默认美元汇率留空，使用最近可用的ECB参考汇率，保留汇率日期和来源；可手工指定业务汇率。自动汇率必须为近7天内有效数据，不能获取时不猜测。

旧版等待千牛与独立重量误差验证保留在 `workflow_mode=legacy_consult`，仅用于旧队列兼容；不属于当前默认流程。以下旧版咨询说明仅适用于此模式。离线测试不等于智赢与1688实站验收，实际结果以执行批次记录为准。

## 启动

已有控制台依赖可直接使用。独立运行的最小依赖：

```powershell
python -m pip install -r erp/ai_weight_price/requirements.txt
python -m erp.ai_weight_price
```

浏览器打开 `http://127.0.0.1:5018/ai-weight-price`。此入口连接当前服务器 MySQL，仅监听本机回环地址，且保留页面内启动控件。集成泽顺控制台时，从浏览器右上角的泽顺插件进入「核重核价」启动；插件必须连接 `http://127.0.0.1:5000` 本机控制台，登录账号还需具有 `ai_weight_price.view` / `ai_weight_price.execute` 权限。远程控制台或远程插件地址不能启动本机 Edge 任务。

```powershell
# 仅首次配置 API 时，设置启动进程的环境变量；不要把真实密钥提交进 Git
$env:DASHSCOPE_API_KEY="在这里填入你自己的密钥"
python -m erp.ai_weight_price

# 配置完成后，自动恢复尚未完成的处理任务
python -m erp.ai_weight_price --run

# 自定义运行目录（仅 Edge 配置/截图等运行环境）和端口
python -m erp.ai_weight_price --data-dir .\output\ai-weight-price --port 5018
```

macOS 使用同样的 Python 模块，环境变量用 `export DASHSCOPE_API_KEY=...`。也可使用环境变量 `AI_WEIGHT_PRICE_DATA_DIR` 指定本地运行目录；该目录不再保存核重核价业务数据库。

如果已有旧版本本地数据库，先启动 MySQL 配置，再执行一次迁移（源 SQLite 文件只读，迁移完成后仍保留为备份）：

```powershell
python scripts/migrate_ai_weight_price_to_mysql.py
```

服务器 MySQL 必须是可写主库；如果 `read_only` 或 `super_read_only` 为 `ON`，页面仍可查看历史数据，但采集、状态更新和回写会失败。确认不是复制从库后，由数据库管理员按运维规范关闭只读保护，再重启工作台。

Windows 上，程序优先读取启动进程的密钥环境变量；进程未继承时，读取当前 Windows 用户持久化保存的同名环境变量。启动检查与实际模型请求使用同一读取规则，不需要把密钥填入页面、配置文件或源码。模型连接检查仅保存通过状态、模型名和时间，不保存密钥。

集成控制台的启动方式沿用项目 README。打包规则原有 `collect_submodules('erp')` 和模板目录收集会包含新模块；本次未重新打包或部署公网控制台。

## Edge 登录会话

使用泽顺插件「核重核价」中的“打开智赢登录页面”按钮，在本机任务使用的 Edge 中打开智赢，无需手动启动调试端口。1688登录在执行商品时检查；如因登录或人机验证暂停，可从插件打开1688页面，完成处理后勾选确认并点击“继续核重核价”，保留原任务范围和进度。独立运行页面仍可同时打开两个登录页。模块在数据目录内使用 `edge-profile` 持久化配置，保留人工登录会话，不要求关闭日常 Edge 窗口。账户密码由人工输入；点击确认后，程序检查智赢后台页面与登录状态；只保存确认时间和浏览器会话标识，不保存密码或导出登录凭证。

默认 CDP 地址是 `http://127.0.0.1:9222`，只接受本机回环地址。若此端口被其他浏览器占用，请在参数设置更换空闲端口，再点击登录按钮。Windows/macOS会自动寻找 Edge 的标准安装位置；自定义路径可通过 `AI_WEIGHT_PRICE_EDGE_EXECUTABLE` 指定。

“终止并清空本次任务”会在当前浏览器操作安全退出后，清除本次批次列表、进度、暂停状态和范围选择；历史商品、历史批次、人工登录页、Edge 登录状态以及商家去重安全记录保留。后续1688搜索和咨询也复用同一个可见 Edge 会话。连接检查会拒绝无头浏览器。

## 可见浏览器与人工恢复

上传使用当前商品的原图文件；自动化会将当前操作的1688页面切到前台，方便操作者看到真实网页。控制台不提供主图或步骤截图面板，执行证据以任务记录、修改前后数据、页面回读结果和运行日志为准。

主图上传后最多等待30秒。没有返回可读取的新结果时，以“搜索超时、无法确认完全匹配”记录技术异常并暂停当前商品；这不代表已证明平台没有同款。1688登录、验证码或人机审核会产生“等待人工处理”日志并暂停，当前商品不计入已处理数量。人工处理完成后打开开关，系统先重试该商品，再继续批次剩余商品；若仍未通过，会再次暂停，不会卡死或误写智赢。

## 页面适配

默认开启 `supplier_auto_adapt`。`supplier_title`、`supplier_image`、`supplier_merchant`、`sku_rows`、`sku_label` 留空时，启动检查不再要求先手工填写；打开每个1688商品详情页后，读取可见DOM节点，由配置的模型选择实际节点编号，再回读验证。模型不能提供代码、CSS或虚构字段值。验证通过的定位规则仅在当前页使用，不保存为全站通用配置；每个页面重新识别，适配成功或失败均写入商品的 `supplier_adaptations` 及运行日志。不会读取输入框值、Cookie、Storage或脚本作为模型输入。

自动适配仍要求页面提供可核验的商家和SKU稳定ID，以及每行完整变体规格。未展开的规格组合、重复ID、节点变化或无法确认的模型输出会暂停当前商品，不会以行号或最低价替代。此功能已有离线合成页面回归测试，真实1688页面兼容性仍须通过实际运行验证。

在「参数设置 → 页面字段适配」可关闭自动适配，或填写实际 CSS 选择器覆盖相应字段；均针对实时 DOM，无网页 API 抓取。字段含义如下。

| 字段 | 要求 |
| --- | --- |
| `erp_rows` | 每件 ERP 商品的容器；默认 `.product-item` 来自已有智赢采集代码 |
| `erp_id` | 卡片中的 ERP 核心商品主键。默认 `.product-id` 找不到字段，或此项留空时，会点击该商品标题，从智赢详情页读取产品编号，并核对标题或主图及详情切换；自定义选择器仍要求唯一。不会拿外部 listing ID、标题或列表序号代替 ERP 主键 |
| `erp_title` / `erp_image` | 卡片中的标题、主图 img；默认 `.product-title` / `img.product-pic` |
| `erp_description` | 商品描述；未配置时保留商品卡片完整可见文本 |
| `erp_sku` | 明确目标颜色、尺寸、型号、包装数量的唯一 SKU 描述 |
| `erp_reference` | 独立参考重量，须带 g/克/kg/公斤/千克单位 |
| `erp_edit_link` | 编辑链接 `<a>`，使用实际 href，不猜测编辑地址 |
| `erp_next` | 仅匹配可用的下一页按钮；不可匹配禁用按钮 |
| `erp_search` | 智赢分类筛选的搜索按钮，可留空自动识别。自动识别兼容“搜索”“搜 索”及图标按钮，多个搜索按钮时按分类所在区域定位；无法唯一确定时停止并记录诊断，可填写精确选择器 |
| `image_search_open` / `image_search_upload` / `image_search_submit` | 1688以图搜货入口、文件输入框、提交按钮；入口和提交可留空表示直接上传后自动搜索。上传字段默认 `input[type='file']`，必须唯一；上传当前ERP商品的主图，支持隐藏上传控件。旧标题搜索字段不再使用 |
| `result_links` | 真实候选详情页链接；限制到 `detail.1688.com` |
| `supplier_title` / `supplier_image` / `supplier_description` | 详情页商品信息；描述未配置时读取页面可见文本，保留原文用于SKU归属核对 |
| `sku_weight` / `supplier_weight` | 可选的SKU行重量/详情页包装重量；未配置时仍会尝试从SKU行和详情可见文本提取明确的目标规格包装重量 |
| `supplier_merchant` / `supplier_merchant_attribute` | 商家身份元素及其稳定 ID 属性 |
| `sku_rows` / `sku_id_attribute` | 每一个可供货 SKU 行与稳定 ID 属性 |
| `sku_label` / `sku_price` | 每行目标规格和确定的人民币单件单价；在基础价加价模式中，sku_price 为基础价 |
| `sku_surcharge` | 基础价加价模式下的变体加价金额（人民币，允许明确的0）；最终单价模式不读取此项 |
| `chat_open` | 详情页客服入口。须能打开有独立、可恢复地址的网页会话 |
| `chat_identity` / `chat_identity_attribute` | 会话所属商家 ID；必须与货源商家一致，支持 iframe |
| `chat_input` / `chat_send` | 输入框与发送按钮 |
| `chat_messages` | **仅商家发来的入站消息**，排除本人消息、系统欢迎语、已读提示 |
| `chat_message_id_attribute` | 稳定且唯一的消息 ID |
| `chat_message_time_attribute` | Unix 秒或毫秒时间戳；用于排除旧消息及超过回复期限的消息 |
| `risk` | 可见验证码/风控弹层 CSS；另有操作频繁、发言受限等文本检测 |
| `erp_edit_id` / `erp_edit_sku` | 编辑页商品主键及 SKU；两项必须与任务完全一致 |
| `erp_net_income_input` / `erp_weight_input` | 智赢净收益输入框（整数美元）与包装重量框（克），必须唯一；净收益默认 `.curd-detail-wrap #netproceed`。旧版 `erp_cost_input` 只保留兼容配置，已不用于回写 |
| `erp_save` / `erp_saved` | 保存按钮与本次保存成功后才出现的提示；之后刷新回读数值 |

如果网站只提供桌面千牛协议、无可恢复网页会话、SKU 需要多级点选后才露出价格，或页面不提供消息 ID/时间戳，当前通用 DOM 适配器会标记异常，需要进一步编写该页面专用适配，不能随便填写近似选择器强行运行。

ERP 商品 ID 是任务主键。同一个父商品有多个变体且无法确定唯一 SKU 时，不应该任取最低价或任意变体。先把 ERP 任务定义到明确可编辑的目标 SKU，再开始匹配。

## 旧版咨询流程和恢复（legacy_consult）

1. 每采集一个商品，持久化商品ID、主图、SKU及来源页，马上处理这一件。页内商品全部完成后才推进页检查点；停止后优先恢复当前商品。重复商品保留历史状态、人工修改和证据。
2. 在1688上传这件商品的主图执行以图搜货。图片大小限制10MB，上传控件必须唯一；等待新的搜索结果，不使用首页推荐商品或旧结果。仅读取有限候选详情。
3. 同款初筛与复核均比较主图、标题、描述、目标规格；两次必须选择同一实际SKU，且分数大于等于配置门槛（至少0.95）。
4. 优先读取目标SKU的最终成本、变体加价、单件含包装总重量。页面原文和提取证据入库。缺少明确价格不会直接丢弃已匹配SKU；包装重量与成本都齐全时直接进入回填。
5. 只有缺少重量或成本时才咨询千牛。消息附实际商品链接及SKU，只询问缺失项目，成本要求包含变体加价。聊天字段仅在此分支使用。先事务预占商家和限额再发送，商家永久去重。
6. 当前商品等待回复期间不采集或处理下一件。默认每15分钟轮询，30分钟超时；分多条回复时合并原文，保留已获取的页面信息，直到信息齐全或超时。只有发送后的新入站消息用于提取。
7. 根据独立对照校验重量，按目标变体最高价加 ¥5 后再按汇率向上取整计算美元净收益。开启自动回写后核对编辑页商品ID及SKU，保存修改前数值、计划修改值和保存后回读值，回读一致才标记成功并继续下一件。任务详情也支持人工填写重量和净收益后直接执行智赢回写，成功后记录“人工核验”；候选未通过完全匹配审核时记录为已屏蔽并继续；搜索超时、读取或保存失败等技术异常暂停当前商品，处理完成或人工跳过后才继续。
8. 默认每次最多10件。累计保存成功与未完全匹配跳过达到10件后立即停止，不采集第11件。Excel分别记录成功、跳过、异常及原因，跳过商品不生成虚假的修改前后值。任务页可导出本次批次或全部产品的Excel；CSV仍保留。MySQL 的 `erp_ai_weight_price_runs`、`erp_ai_weight_price_run_items` 保存批次及每件商品快照，`erp_ai_weight_price_tasks` 保存最新进度，`erp_ai_weight_price_events` 保存日志。启动适配检查失败也会为范围内最多10件已有待处理商品留下“启动受阻”记录，不会伪造回填值或将其标记为成功。

Excel包含执行结果、失败原因、SKU、人民币成本、重量、美元净收益、修改前重量/净收益、计划修改值、修改后回读值、保存验证、资料来源、汇率日期、货源链接、核验方式和时间。没有读取或没有执行的数值保留为空；“计划修改”不等于“修改后回读”。每次回填尝试的原值和目标值写入 `write_history`，失败重试也不覆盖旧审计证据。

`pending` / `waiting_merchant_reply` / `success` / `exception` / `skipped` / `blocked` / `risk` 为七种业务状态，`stage` 记录内部执行位置。运行中关闭进程后，后续可继续已有队列；`send_reserved` 或 `writing` 阶段中断，因无法确认外部副作用，恢复时转为异常，交人工核对。手动重试已有会话只重新读回复，不再次向商家发送消息；商家永久去重记录不删除。修改目标 SKU 会使旧匹配证据和重量失效，需要重新匹配。

## 旧版咨询限流与公共熔断

- 每日默认25个商家咨询，按北京时间自然日；可调整当日硬上限。预占/结果不确定的发送也计入当日限额。
- 同一商家永久唯一，数据库唯一索引兜底；不同商品也不会再次咨询该商家。
- 两次咨询至少间隔60秒；配置只能提高间隔。
- 逐件流程一次只等待当前商品；数据库仍保留最多2个会话的历史兼容硬上限。
- 打字后再随机等待1–3秒点击发送；话术至少2条不同文本。
- 验证码、频繁操作、发言受限触发持久化熔断。停止本次处理，不自动重启；人工处理页面后才能解除。
- 达到日限额后暂停新咨询，已发送会话仍可轮询；其余任务设置为次日再尝试。进程保持运行时跨日继续，关闭后用「继续」或 `--run` 恢复。
- 跨进程锁避免同一执行端的重复任务；MySQL 事务和唯一索引保证商家去重与预占的原子性。多台电脑通过服务器 MySQL 共享同一队列，不要让多台电脑同时启动同一执行批次。

随机延时不保证平台不会触发风控；这里只做节流和遇到限制停止，不绕过验证。

## 旧版独立重量误差验证

令 `w` 为1688页面或商家回复提取的包装重量，`r` 为 ERP 原参考重量或人工实测重量：

```text
w <= 500g：abs(r - w) <= 50g
w >  500g：abs(r - w) <= 30g
```

阈值可收紧、不能在配置中突破50/30g。500g正好采用50g档。缺少 `r` 就无法计算误差；不允许拿 `w` 与自身比较后判通过。校验只是两个数值是否接近，不证明商家给出的重量等于真实实测值。

## API 与硬件选型（2026-09-06 核查）

建议先采用 **Qwen3-VL-Flash 初筛 + Qwen3-VL-Plus 复核**。两者支持视觉输入，适合商品图片与中文规格。没有在本公司的真实商品集上做过模型对比，因此不能承诺这是所有API中实测性价比最高、或任何模型固定达到95%准确率。

| 模型 | 每百万输入/输出Token，北京地域，输入≤32K | 用法 |
| --- | --- | --- |
| Qwen3-VL-Flash | ¥0.15 / ¥1.5 | 所有候选初筛、商家文本重量提取 |
| Qwen3-VL-Plus | ¥1 / ¥10 | 只复核初筛高分候选 |

官方实时价格和区域差异见 [百炼模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)。估算：每次候选输入6000、输出400Token，Flash约¥0.0015，Plus约¥0.01；每商品默认初筛10次，实际成本随候选数量、图像分辨率、Token量和失败重试变化，运行日志记录API返回的Token用量。相比一开始投入本地推理维护，这个规模先用API更便于评估。

| 设备 | 本地建议（需实测） |
| --- | --- |
| M5 MacBook Air 16GB | Qwen3-VL 4B 量化版先试；8B可做小上下文评测，留出浏览器和系统内存，Air持续负载性能需实测 |
| M4 Mac mini 16GB | 同样先4B；更适合固定放在办公室做低并发服务，8B需控制上下文与图片数 |
| RTX 4060 Ti，32GB系统内存 | 本机 `nvidia-smi` 实测8188MiB显存，即8GB版本。优先4B量化，8B模型权重加KV/视觉缓存可能挤满显存，不建议作为默认长上下文服务 |

[Ollama 官方模型库](https://ollama.com/library/qwen3-vl)的4B模型包约3.3GB、8B约6.1GB；包大小不是运行总内存。建议从4K–8K上下文、两张缩放图片、单推理并发开始。模型本身支持更长上下文，不代表16GB机器可以把最大上下文开满。

```bash
ollama pull qwen3-vl:4b
ollama serve
```

然后 API 基础地址填写 `http://127.0.0.1:11434/v1`，初筛/复核/提取模型均填写已安装模型名。接口格式参考 [Ollama 兼容API](https://docs.ollama.com/api/openai-compatibility)。同一个本地模型运行两遍并不相当于独立正确性保证，建议本地做初筛、暂以人工复核抽样为主，评测后再决定全本地。模型能力与部署参见 [Qwen3-VL 官方仓库](https://github.com/QwenLM/Qwen3-VL)。

### 如何验证“95%”

先标注200–500组真实商品/候选，包括外观近似但尺寸、颜色、材料、每包数量不同的困难负例。重点统计自动通过样本中的正确比例（precision）、错误放行数、拒绝率和每件成本，分品类评测。不要只检查模型自报 `confidence`。逐条人工复核试运行结果，确认商品与SKU、包装重量对照和ERP单位无误后再启用自动回写。
