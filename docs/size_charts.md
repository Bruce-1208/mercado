# 尺码表管理

入口：工作台「店铺管理 → 尺码表管理」，点击后在工作台内打开「尺码表管理」标签页。切换到其他工作台标签再返回会保留已打开的尺码表页面与未保存草稿。也可直接访问 `/size-charts`。

本模块复用美客多店铺授权，可维护多份尺码表模板，并将保存的模板上传给所选店铺的多个站点。模板按企业隔离，上传和记录查询继续受当前账号的店铺权限限制。

## 使用流程

1. 在「内置常用品类参考模板」选择商品与人群，预览已填数值，点击「使用并保存模板」；也可从左侧选择已有模板。尺码、测量值及单位立即显示，无需先读取官方规格。
2. 选择其他授权店铺及站点，点击「校验并预览」，通过后上传。默认沿用模板名称，不需要重复填写尺码数据。
3. 「下载模板」导出完整模板 JSON，可导入本系统复用。JSON 是本系统模板格式，不表示平台后台支持直接导入文件。
4. 需要修改时展开「维护模板内容与官方规格」，读取官方字段并编辑，保存新版本后再上传。

## 内置完整参考模板

内置 21 套参考模板：男装、女装各包含 T 恤、衬衫、长裤／牛仔裤、短裤、夹克／外套、卫衣、睡衣；另有女装连衣裙、女式上衣、打底裤，以及男童、女童各自的 T 恤与长裤。成人模板 7 个尺码，童装模板 6 个尺码。

数据版本为 `2026.10.02`，由系统人工编制为通用参考配置，不来自任何品牌实测或国家尺码标准。按人群分别预填身体胸围、腰围、臀围、身高、颈围的厘米范围；下装仅保留腰围、臀围和身高。字母码、数字腰码与儿童年龄标签分别维护，不提供国际尺码自动换算。商品按相同范围选码时可直接复用，品牌默认 `Generic`；有品牌的商品应修改为对应品牌。

选择时已经包含类目、性别、品牌、主尺码、平台名称、全部尺码行及数值结构。点击「使用并保存模板」保存独立副本，不会修改内置原版或直接提交平台。「下载完整模板」导出本系统可导入的单份完整模板 JSON，不包含店铺凭证、卖家编号或平台尺码表／尺码行编号。

服务器上传预览按各店铺实时规格，将内置模板中的尺码标签精确匹配到官方枚举编号。标签不匹配、存在歧义、缺少其他必填字段、单位不受支持时阻止上传；不猜测或换算等价尺码。目标规格未接收的已知参考列仅在本次提交副本中省略，预览明确列出省略项；保存的原模板保持完整。没有任何可接收的身体测量列时，也会阻止上传。用户新增的未知属性不会自动省略。

参考来源标记会随保存、复制、JSON 导入导出及上传快照保留。页面底部折叠的「品类与尺码填写参考」仍是辅助新建的标签目录，和上述 21 套完整数据模板分开显示。

## 品类填写参考

标准库包含 24 个常用品类：成人上衣、外套、裤装、牛仔裤、连衣裙、半身裙、西装、运动服、泳装、文胸、内裤、婴儿服装、童装、成人鞋、童鞋、婴儿鞋、袜子、帽子、手套、腰带、戒指、箱包、家居纺织品及通用商品。未列出的商品可从通用规格开始编辑；是否能创建平台尺码表仍取决于官方支持域。

字母尺码与各品类适用的 EU、US、UK、BR、月龄、身高、W/L、胸围码＋杯型、戒指码等体系分别维护。标签是可删减、可补充的起始清单，不代表等码关系、完整品牌供应范围或官方允许值。儿童年龄与身高、文胸杯型和不同地区鞋码均不自动换算。

「测量项目与填写规范」提供参考项目和方法，不提供实际数值或官方属性 ID。胸宽、腰宽等成衣平铺单面宽度与人体胸围、腰围分开测量；足长与鞋内长／鞋垫长分开记录；戒指内径、内周长与手指围分开记录。每款商品按其品牌资料或实际测量填写。字段、测量类型、单位、可选尺码与最大行数以所选店铺的实时官方规格为准，参考单位不能覆盖官方限制。

鞋类数字主尺码按官方允许的尺码单位生成（例如 US），与模板选择的地区体系必须一致；不同体系不会自动转换。

生成尺码行会保留草稿已有的尺码及实测值，并跳过相同主尺码标识；调整尺码体系或追加行后需核对整份草稿。若官方行数上限较小，先删减至实际销售尺码后再生成。

「下载品类参考包」导出带版本号的标准库 JSON，包含品类、独立尺码标签和测量说明，供所有店铺复用参考。它是草稿规范包，不是已填写的平台上传请求。编辑区「导出 JSON」导出当前店铺规格下已编辑的模板，可用于导入或复制后复用。模板库不包含店铺授权、卖家 ID、官方尺码表 ID 或实测数据。

复制模板可以复用已有的测量数据。编辑本地模板会增加版本；再次上传使用新版本。删除本地模板不删除平台尺码表，历史上传记录保留。

跨境卖家创建的是父卖家拥有的 CBT 尺码表，同一卖家的多个目标站点合并为一次创建；不同店铺分别创建，不能共用另一卖家的尺码表 ID。服务器确定卖家身份和实际开通的站点，不采用浏览器提交的卖家 ID。

模板名称与平台名称分开处理，上传使用的站点名称需符合官方限制。尺码表字段、必填属性、枚举值和单位以运行时读取的类目规格为准。官方不支持自由修改已上传尺码行，需修改测量值时维护新的模板版本并创建新表。

## 结果核对

上传记录保留模板快照和提交参数。同一模板版本在同一店铺成功提交或结果未确认后不会重复创建；新增站点需要保存新版本后重新预览。网络超时或服务中断可能发生在平台已收到请求之后，此时应先核对平台尺码表及记录，再继续处理。

对待核对或中断的记录，可点击「核对上传结果」，填写从平台确认的尺码表 ID。服务器只读取官方记录，验证卖家、站点、类目、主属性及完整尺码数据是否与原上传快照一致；匹配后补全记录，不重新创建尺码表。

上传尺码表只创建可供商品使用的表。商品关联需要在上架或商品维护时使用该店铺的 `SIZE_GRID_ID`，以及对应尺码的 `SIZE_GRID_ROW_ID`。

## 部署与权限

无需新增第三方依赖。更新后重启工作台；Web/worker 分离部署时需同时更新并重启 Web 和 worker，客户端通过受保护的中心接口访问数据。

客户端和中心服务须配置相同的 `BIT_DB_API_TOKEN`；此模块的内部接口不允许无凭据的本机访问。

新增权限 `size_charts.view`（查看及读取官方规格）和 `size_charts.execute`（维护模板、预览、上传）。系统角色按现有角色初始化流程补齐权限；自定义角色可在人员与权限中配置。

中心服务自动初始化 `.data/size-charts.sqlite3`；使用 `BIT_SIZE_CHART_DB_PATH` 可指定存储位置。备份需包含该数据库；运行中备份应使用 SQLite 备份接口，以包含 WAL 中尚未合并的数据。
