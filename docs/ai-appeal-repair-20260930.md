# AI 话术记录缺失与生成失败修复

核查时间：2026-09-30，北京时间。来源为当前 MySQL 的 ai_appeal_records 和本机 Agent 事件库，只读核查，未发送真实申诉。

## 根因

数据库中 AI话术模式共 3,062 条记录（2026-09-26 至 2026-09-27），其中执行失败 3,036 条、需要登录 26 条，实际发送话术均为空。2,768 条错误包含商品标题 HTTP 403。记录含站点汇总，不能视为独立申诉次数。事件库未找到“生成 AI 话术”成功日志，也未找到 DeepSeek 生成报错；主要故障发生在调用模型之前。

页面先读取全模式最新 500 条再本地筛选，因此后续普通模式记录会挤掉旧 AI 记录。记录并未丢失。

原商品资料加载器匿名请求 /items/{id}。真实只读检查发现，即使携带店铺授权，该路径仍为 403；使用店铺授权访问 /marketplace/items/{id} 返回 206 和有效标题。样例 MLB7688237100 的描述路径返回明确 404，说明还需处理缺失描述。

## 修复

- 侵权和禁限售 AI 话术均通过服务端的店铺授权获取商品事实，使用 Global Selling 商品接口。店铺名称必须唯一匹配启用的授权。一次最多 3 个合法商品编号。
- Agent 只接收商品事实，不接收店铺 Token。新增内部接口沿用运行中 daily_task 的 Agent 鉴权；支持授权过期刷新，限制请求超时，不向日志输出原始凭证或上游异常。
- 描述明确 404 时以空描述和真实标题生成理由，保留原有不得编造事实的提示词；403、网络失败和空标题仍中断生成。
- 话术模式在数据库 LIMIT 之前筛选，贯通内部接口和页面接口；页面切换模式和重置时重新读取，过期响应不会覆盖新结果。日期、业务员等其他筛选仍作用于本次取回的最多 500 条记录。

## 验证

- Python 相关回归：42 passed；前端模式切换与重置：1 passed。
- 编译与改动文件 diff 空白检查通过。
- 真实只读商品验证：成功读取样例标题（48 字符），描述确认为缺失。
- 真实数据库运行新查询：返回 500 条，全部为 AI话术模式。
- 扩展回归另发现 3 个既有断言不匹配：executor 元数据新增字段、点击即确认发送的 message_id、插入字段下标。对应三个生产函数 AST 与 HEAD 相同，本次未改动；未将这些失败宣称为通过。

## 生效范围

本次完成工作区源码修复，未重启运行中的服务端和 Windows Agent，未重新提交历史申诉。需先更新并重启服务端，再更新远端业务包、重启申诉任务；旧进程不会自动加载新代码。工作区含大量其他未提交改动，本次未将其一起部署。无需删除或重写已有失败记录。
