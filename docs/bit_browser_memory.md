# 比特窗口内存回收修复（2026-09-21）

## 已确认的问题

- `bit/logs/bit_daily_task_console_b3a763011ce9849c.log:16634` 起，2026-09-21 01:24:10 多个店铺关闭窗口失败，本机 `127.0.0.1:54345` 拒绝连接。日志证实关闭链路中断，不能单凭该日志确定操作系统最初是否因内存不足崩溃。
- 旧 `bit_api` 的三个槽位只限制打开/关闭 HTTP 请求；请求完成就释放，并未限制存活窗口数。daily_task 默认 15 个 worker，多批任务还能叠加。
- 单次 AI 申诉结束只清理标签页和 ChromeDriver 服务，再释放窗口锁；完整 Chromium 窗口仍存活。人工客服申诉还有浏览器连接失败、帮助页面提前返回时绕过清理的问题。
- `/browser/close` 返回成功不等于浏览器主进程已经退出。关闭失败后旧代码释放锁，批量任务登记表也无法跨主进程重启恢复。

## 修复行为

1. 公共 `openBrowser` 在发请求前向 SQLite 登记窗口；所有 worker、采集及申诉任务共享容量。默认最多 3 个窗口，计入待启动、未确认关闭和 PID 接口检测到的人工窗口。低于 15% 可用内存时暂停新开窗口；已有窗口仍允许连接、清理。Windows/Linux 使用系统可用物理内存；macOS 使用系统 `memory_pressure -Q` 指标。指标读取失败时仍保留窗口数量保护。
2. `closeBrowser` 调用后查询 `/browser/pids/alive`，最多短轮询三次。只有主进程不再存活且不存在启动结果不确定的保护期，才能释放登记。状态查询失败时保留登记。这里只核验 BitBrowser 报告的主进程，不承诺检测内核脱离主进程的所有异常子进程。
3. 工作台、bit_main 和打开窗口的 worker 启动后台回收，每 15 秒巡检。回收只针对登记过且能取得窗口独占锁的自动任务窗口。关闭失败继续留档；下一次巡检、服务恢复或程序重启后继续尝试。不会因任务耗时长就关闭活跃窗口。
4. 单次 AI 申诉和人工客服申诉覆盖正常结束、连接失败、异常和提前返回，清理驱动服务和完整窗口。批量 AI 申诉继续由外层店铺任务管理窗口，避免中途关闭。明确移交给人工的窗口保留，仍计入容量。
5. 窗口启动请求超时不能推断“没有打开”。登记保留到请求超时预算加 120 秒保护期后再次回收，避免迟到的窗口成为遗漏项。等待容量的进程共享两秒的 PID/内存快照，避免新保护机制本身触发接口限频。

接口语义依据：[BitBrowser 官方浏览器接口](https://doc.bitbrowser.cn/api-jie-kou-wen-dang/liu-lan-qi-jie-kou)。

## 启用与限制

- 重启使用旧代码的工作台、bit_main 和自动任务进程后生效；仅更新磁盘文件不会替换运行中的 Python 模块。
- 状态文件为 `BIT_RUNTIME_LOCK_DIR/browser_lifecycle.sqlite3`。未设置时仍使用项目 `bit/runtime_locks`。同机多份代码或多个 Agent 业务版本必须使用相同的固定 `BIT_RUNTIME_LOCK_DIR`，才能共享窗口锁、容量和回收登记。不要在任务运行时删除此目录或数据库。
- 默认配置见 `.env.example`。环境变量必须由实际启动器注入；复制示例文件本身不保证启动器自动加载。
- 等待窗口容量使用调用方的 `api_lock_timeout`，普通后台任务默认 `BIT_BROWSER_API_LOCK_TIMEOUT=180` 秒；到期明确报资源不足，由现有任务重试策略处理。长时间占用窗口的任务应相应降低业务 worker 数，避免大量任务同时排队超时。
- 首次升级前已经遗留的窗口没有自动任务归属记录，会计入容量但不会擅自关闭。需要在确认旧任务停止后人工关闭遗留窗口，建立干净基线。
- 如果 BitBrowser 本机 API 一直不可用，程序会停止新开窗口并持续重试回收，无法通过失联接口强制释放它的进程。需要恢复 BitBrowser 客户端。此修复不包含按进程名批量杀掉用户浏览器的操作。

## 验证

回归覆盖多个独立进程竞争同一容量、低内存禁止新开、启动超时后迟到窗口、关闭返回成功但 PID 存活、PID 查询失败、关闭失败后再次回收、强制终止 worker 后恢复、线程退出遗留锁、人工窗口保护，以及申诉连接失败时的完整清理。

生产验收应观察至少一个完整任务周期：结束后已登记自动窗口数归零（明确手工接管除外），任务停止后残留被回收；窗口数稳定受限，系统可用内存不再随任务轮次持续下降。当前代码测试不能代替目标服务器的实际长时间负载验证。
