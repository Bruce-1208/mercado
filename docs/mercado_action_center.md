# 美客多通知与今日必办

## 接入

在美客多应用管理中，将通知回调地址设为公网 HTTPS 地址：

```text
https://<工作台域名>/api/mercado/notifications
```

订阅 `marketplace orders`、`marketplace shipments`、`marketplace items`、`marketplace questions`、`marketplace messages`、`marketplace claims`、`marketplace fbm stock`、`marketplace item competition`、`public offers` 和 `public candidates`。需要商品族或 CBT 迁移事件时，也可订阅 `marketplace_user_products`、`marketplace_user_products_families` 和 `marketplace_cbt_items_uptin`。

回调应指向运行在 server 角色的工作台。首次启动会建立通知事件、运营待办和处理记录表；web/worker 分离部署时，服务拆分会把回调转到 worker。回调校验应用 ID 与卖家 user ID 对应的已启用店铺授权，先在 MySQL 持久化通知和待办，再返回 HTTP 200；数据库不可用或店铺归属不明确时返回 503，让美客多重试。API 详情读取在后台执行，失败后按退避策略重试，最多 5 次，之后可在“今日必办”的通知记录中手动重放。

请确认“店铺授权”中每家店铺保存了正确的美客多应用 ID 和卖家 user ID。一个应用可以关联多家店铺；通知中的 `user_id` 会用于精确匹配店铺，再按该店铺所属企业隔离待办。若卖家 ID 缺失或无法唯一匹配，回调会返回 503 并在服务日志中说明授权配置问题。

## 运营页面

登录成功后默认进入“今日必办”，也可直接访问 `/mercado/today`。普通订单通知按订单创建时间仅显示最近 30 天的订单；订单履约告警不受此限制，超过 30 天仍未完成的订单会继续提醒。查看需要 `tasks.view` 权限；分派负责人、调整截止时间、更新状态、记录处理结果和重放失败通知需要 `tasks.execute` 权限。任务按店铺隔离，包含原业务入口、截止时间、负责人、状态和最近处理记录。

当前会生成以下待办：

- 页面单独展示当前店铺权限范围内的待回复权利人案件（`WAITING_DOCUMENTATION`），按回复截止时间排序，显示商品、案件编号、原因与最近同步时间。“去回复权利人”在新窗口打开美客多官方权利人举报页，使用对应店铺账号选择案件并回复。今日必办的权利人案件状态每小时从官方案件接口同步一次，打开的页面也每小时重新读取；平台确认回复后，该案件会从待回复列表移除。

- 订单、运单、售前问题、售后消息、索赔、商品、库存、促销和商品竞争通知。后台按通知 resource 查询最新美客多资源；运单/待发货订单优先读取 `pay_before` 作为官方发货截止时间。
- 本地订单快照中超过 12 小时没有更新的待发货订单，提示运营到美客多核对发货时限；采购物流查询超过 48 小时仍处于无轨迹或异常状态时提示跟进。
- 本地活动快照中 48 小时内到期或最近 7 天到期但仍未标为结束的活动。
- 促销任务里执行结果未知的项目，提醒运营到活动页核对平台实际状态。
- 已停用、过期或告警状态的店铺授权。

平台回调与 `missed_feeds` 恢复扫描每 15 分钟运行；现有订单定时同步继续作为订单兜底。今日必办页面每小时自动刷新一次。API 处理状态为“已处理”仅表示通知 resource 已成功读取；只有运营人员将对应待办标为“已完成”并记录结果，异常才会从未完成列表移出。

商品通知当前可以识别暂停、关闭、审核中和平台可售库存为 0 的情况。与仓库 ERP 库存的逐 SKU 数量差异、问题/消息线程的自动未回复判断，以及索赔 API 未返回截止字段时的真实平台 SLA，仍需要单独补充对应数据源或业务规则；页面会要求运营进入平台核实，不把内部建议时限当成官方时限。

### 采购必办与筛选

“采购必办”按订单创建时间提醒：超过 24 小时未填采购订单号、满 48 小时未填采购物流号、满 168 小时仍未在途中、满 30 天仍未交付。48 小时、168 小时和 30 天规则在达到时限时即触发，订单最近更新不会重新计时。平台订单时间按数据库中的 UTC 时间计算，并以北京时间展示。

已在途中仍缺采购物流号的订单会保留缺号提醒；补齐物流号后该提醒自动结束。进入正常在途后，168 小时提醒自动结束，但 30 天未交付提醒仍保留。交付、取消或全额退款后系统自动结束对应履约提醒；已入库、交付失败、部分退款和物流异常不等于已交付，异常流程也不算正常在途。系统自动结束后再次满足告警条件时会重新提醒，人工标记完成的记录保持完成。

订单和待办均按批次完整读取，避免大量旧记录挤掉告警。处理明细与待办记录在同一数据库事务中保存，并追加到 `order_remark`（订单备注），保留原备注，不写入采购备注。追加后超过 5000 字会拒绝保存并提示整理备注。

页面可组合选择业务员和店铺组，按店铺授权中的归属筛选采购及运营待办、权利人案件、通知记录；选项限定在当前账号有权限的企业和店铺内。员工任务继续显示分配给当前账号的任务。

### 未回复售后消息

今日必办单独加载“待回复售后消息”，不按消息日期筛选。候选范围为官方未读 Pack 与本地已同步订单的全部 Pack（没有 Pack ID 时使用订单 ID）；完整分页读取会话并按消息时间判断最新发送者。最新消息来自买家时显示，即使已读也保留；最新消息来自卖家时不显示。旧的消息通知提醒不再混入运营待办，避免重复或将已回复消息继续显示。

列表遵循当前组织、店铺授权、业务员和店铺组筛选。读取失败显示部分结果提示；未同步到本地且平台已标记已读的历史订单无法由上述候选来源发现。进入工作台后在浏览器空闲时预加载今日必办，直接打开今日必办时在页面头部提前请求并复用结果。订单告警计算和售后会话核对按企业、店铺分别复用 60 秒的进程内快照，同一店铺的并发请求合并；切换业务员、店铺组或状态筛选无需重复计算。每次接口请求仍重新检查店铺权限，待办处理记录、通知和权利人案件仍直接读取最新数据。

冷启动和过期快照均在后台计算，接口先返回已有结果及核对状态，页面每 3 秒检查完成情况，隐藏页面暂停检查；未完成首次核对时显示“核对中”，不显示“没有待办”。售后列表展示最近核对时间。点击“刷新待办”或返回页面会强制重新核对，但复用已经在执行的核对任务。每种后台计算最多同时处理 2 家店铺，每家店铺最多并发核对 6 个售后会话，单个会话仍完整读取分页；失败会明确展示，其他会话仍可返回。缓存容量为每类 128 家店铺，服务重启后重新预加载；多进程部署各进程独立预热。首次完整核对仍取决于订单量和平台响应速度，但不再阻塞页面请求。

今日必办按授权并筛选后的店铺 ID 排序，每页加载 20 个店铺，通过“上一页店铺 / 下一页店铺”可遍历全部授权范围（包括系统管理员的跨企业店铺）。各页的数量和统计仅对应当前店铺页；采购、运营、权利人、售后列表每页显示 20 条，通知记录按数据库每页 50 条读取，不再截断为最近 100 条。切换业务员或店铺组会回到第一页。后台缓存队列满时返回核对中并轮询；单个店铺或数据分区异常显示部分读取失败提示，不阻断其他分区。

成员（业务员）和店铺组筛选在当前浏览器按账号及组织保存。重新登录、再次打开今日必办或工作台预加载时，首次请求直接使用上次选择；选择“全部”也会保存。退出登录保留偏好，其他账号使用自己的筛选记录。原选择不在当前授权选项时保留所选范围并提示“当前范围不可用”，可手动重新选择；浏览器禁用本地存储时正常筛选，但不保存偏好。
