# 后台任务重启保护

本次将申诉执行进程与工作台 HTTP 服务的生命周期分开，并为店铺链接同步、批量修改及删除保存恢复所需的记录。重启 Web、中心 worker 或它们的管理进程后，已独立启动的申诉任务继续执行；链接更新由恢复队列接续未完成部分。该保护覆盖下表列出的任务，其他后台功能仍按各自现有实现运行。

## 保护范围

| 任务 | 服务重启后的行为 | 状态及进度来源 |
| --- | --- | --- |
| 服务器/旧本机工作台的 daily_task 自动申诉 | 原独立任务进程继续运行；新服务可读取状态、日志及提交停止请求 | `bit.durable_tasks` 的 SQLite、任务日志及停止文件 |
| 服务器/旧本机工作台的客服申诉 | 查看日志的 HTTP 连接断开后，原任务进程继续运行；可按任务编号重新查看及停止 | 同一独立任务存储 |
| 店铺链接同步 | 已请求或中断的店铺进入恢复调度；保留已同步数据，重新扫描未完成店铺 | MySQL `erp_mercadolibre_store_link_sync_state` |
| 店铺链接批量修改、删除 | 服务 worker 启动恢复队列；跳过已经保存逐链接结果的记录，继续其余记录 | `store-link-remote-update.sqlite3` |
| 店铺链接访问量更新 | 恢复初始扫描游标，继续处理到期商品 | MySQL 访问量调度表及 `store-link-visits-schedule.json` |
| 本机 Agent 正在执行的任务 | Agent 1.2.8 对连接错误、超时、HTTP 429/5xx 保留原业务进程并重试控制连接；重连后执行停止指令 | 固定服务端 Agent 队列及本机任务进程 |

通知事件已有持久化队列、租约与退避重试，继续沿用原机制。侵权筛查、服务器智赢订单同步、商品采集、发布、导出等任务没有统一迁移到本次独立任务进程；不能据此认为所有后台任务都已获得相同保护。

## 独立申诉进程

启动接口先记录任务，再启动 `python -m bit.durable_tasks --run <任务目录> <任务编号>`。POSIX 使用独立会话，Windows 使用独立进程组。任务运行进程不监听 Web/worker 的端口，也不匹配工作台重启脚本的进程识别规则，因此普通工作台重启不会结束它。新任务进程禁用中心自动调度器，避免同时启动另一份同步和定时任务。

SQLite 保存公开参数、创建账号、执行状态及统计，日志直接写入任务目录。API Key 等私有执行参数通过进程标准输入传递，不写入命令行或任务数据库。每个任务持有独立跨进程锁；页面刷新和新服务状态查询读取同一份持久化状态。停止操作先写入任务停止文件，再返回；任务进程及其共享停止控制会检查该文件，所以停止请求也能跨工作台重启保留。

原任务进程运行期间继续使用它启动时加载的业务代码。部署新源码并重启工作台后，新任务使用新代码；运行中的任务不会因为版本变化重新执行。

独立任务进程本身崩溃、被强制结束或整台主机重启时，状态会显示 `interrupted` 并保留日志。申诉不会自动重放，因为退出前可能已经发送话术。此时需要核对实际执行结果，再决定后续任务。旧版本已经启动的进程内任务不会自动转换成独立任务；首次部署应让这些任务结束后再重启。

## 店铺链接恢复

链接同步请求在 MySQL 保存店铺编号和请求版本，店铺开始、完成及失败分别更新对应状态。一次扫描只消费它开始时领取的请求版本，扫描期间新提交的请求会保留下来。重启留下的 `running` 店铺可立即进入恢复调度，无需等待普通失败重试的默认一小时；同一链接写锁仍限制一个活动同步/修改进程。恢复按店铺重新扫描，因此不承诺恢复到某个 API 分页的精确位置，也不保留旧内存任务的全部展示日志。

批量修改和删除先将任务、目标链接、指定修改值写入 SQLite，再执行后台操作。每个链接的结果先提交检查点，再更新展示进度。恢复时只处理没有结果检查点的链接，并继续使用原有共享链接写锁。成功、部分成功及失败结果均保留，已保存结果的链接不会被恢复队列自动重做。

远端操作与本地检查点无法组成一个事务：如果远端已接受修改，但服务在保存结果前退出，该链接可能在恢复时再次设置相同目标值。该机制适用于现有指定值修改和状态设置，不能作为任意外部动作恰好执行一次的保证。删除沿用原有远端状态读取与确认逻辑。

## 部署与数据目录

Web、worker 和独立任务进程必须使用相同的持久化路径、数据库配置及工作台密钥。保留以下数据并纳入现有备份范围：

- `BIT_BACKGROUND_TASK_ROOT`：独立任务目录，包含 `tasks.sqlite3`、任务日志和停止文件。默认位于固定 Agent 队列所在目录下的 `background-tasks`；显式设置必须使用绝对路径。任务和日志保留期沿用 `BIT_DAILY_TASK_LOG_RETENTION_DAYS`，默认 3 天，活动任务不清理。
- `BIT_LOCAL_AGENT_HUB_PATH`：现有固定 Agent 队列路径。保持 Web/worker 使用同一文件。
- `BIT_RUNTIME_LOCK_DIR`：共享进程锁与浏览器窗口锁目录。服务重启时不要删除活动任务的锁。
- `MERCADO_STORE_LINK_REMOTE_UPDATE_PATH`：批量链接操作队列文件，默认 `runtime_logs/store-link-remote-update.sqlite3`。部署更换代码目录时，显式指向固定绝对路径或一并保留文件。
- MySQL 链接同步状态表、访问量调度表及 `runtime_logs/store-link-visits-schedule.json`。

源码修改要经过一次服务部署重启才会让新的启动接口和恢复入口生效。独立任务存储自动初始化，无需新队列服务。单台主机继续只运行一个中心 scheduler worker；不要同时启动旧 combined 服务和分离 worker。

使用外部进程管理器时，需要核对其停止范围。按整个容器、cgroup、用户会话或进程树终止的管理配置也会结束独立任务；单靠独立会话无法覆盖这类停止策略。整机重启仍按上面的任务崩溃边界处理。

## Agent 升级与断线边界

Agent 1.2.8 需要重新构建并替换终端客户端，保留现有配置和身份数据。仅部署服务端业务包不会更新稳定通信程序。注册和任务领取仍需要正常鉴权；断线保护只保留已经领取并启动的任务，不领取离线新任务，也不重启退出的业务进程。

HTTP 401/403 明确拒绝凭证时，Agent 立即停止当前业务进程；本机“结束任务”、退出 Agent 和服务端重连后返回的停止请求仍生效。未识别的控制响应异常保留 12 分钟保护。网络恢复前网页停止请求无法送达终端，可使用终端的本机停止按钮。

服务端默认 15 分钟租约继续有效。长时间失联导致服务端回收任务租约时，重连后仍会停止任务；需要中心数据库接口的业务操作也可能因断线或权限失效而结束。该改动避免普通服务重启的控制连接故障主动杀掉 Agent 工作进程，不承诺所有业务步骤可无限离线完成。日志和已有结果保留在本机，上传失败只重试上传，不重放申诉。

## 验证

回归使用临时任务目录、隔离数据库和模拟远端接口，覆盖服务父进程退出后任务继续运行、重新读取状态及停止、任务进程丢失后的中断识别、链接请求恢复和逐链接检查点恢复。Agent 回归模拟超过 12 分钟的连接/超时/限流/5xx 故障，并检查重连停止和凭证拒绝即时停止。测试不向真实店铺发送申诉或修改商品。
