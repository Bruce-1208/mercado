# 泽顺 ERP 设计规范

适用范围：`bit/templates` 中主工作台、独立工作区和账户页面。Yandex 独立应用和浏览器插件不在本次改版范围内。

## 视觉原则

保留紧凑的企业后台布局：深色导航、浅灰蓝底、白色内容卡片。蓝色用于主操作和选中状态；红色仅用于危险操作或错误，绿色表示成功，琥珀色表示提醒。状态必须同时配有文字，不能只靠颜色区分。

## 共享变量

唯一的视觉变量源为 `bit/static/zeshun-theme.css`。

| 用途 | 变量 / 规范 |
| --- | --- |
| 主色 / 悬停 / 浅底 | `--zs-brand` / `--zs-brand-hover` / `--zs-brand-tint` |
| 页面 / 卡片 / 筛选背景 | `--zs-canvas` / `--zs-card` / `--zs-card-soft` |
| 标题 / 正文 / 辅助文字 | `--zs-heading` / `--zs-copy` / `--zs-secondary` |
| 边框 / 控件边框 | `--zs-stroke` / `--zs-stroke-strong` |
| 成功 / 提醒 / 错误 | `--zs-success` / `--zs-warning` / `--zs-danger` |
| 正文 / 辅助 / 页面标题 | 13 / 12 / 20 px，使用 `--zs-text-*` |
| 间距 | 4 / 8 / 12 / 16 / 24 px，使用 `--zs-space-*` |
| 卡片 / 控件 / 弹窗圆角 | 10 / 6 / 14 px，使用 `--zs-radius-*` |
| 桌面控件 / 手机触控 | 32 / 44 px，使用 `--zs-height-*` |

字体使用系统字体栈 `--zs-font`，不加载远程字体。正文常规字重，标题与选中状态使用 600–700。数值使用等宽数字，金额列在具体模块中右对齐，不能强行右对齐所有单元格。

## 样式职责与顺序

1. 模板及模块 CSS 负责业务组件结构。
2. `zeshun-theme.css` 提供变量与历史组件映射。
3. `console-layout.css` 负责工作台布局和移动导航。
4. `erp-density.css` 负责紧凑间距和控件高度。
5. `design-system.css` 最后加载，统一共享组件外观及交互状态。

新功能优先复用 `.primary`、`.secondary`、`.danger`、`.zs-filter-panel` 和现有表格容器。不要用通用规则改写元素的显示/隐藏、固定高度或业务状态背景。确需例外时限定到模块选择器并写明原因。不要用更多 `!important` 解决普通的样式顺序问题。

## 组件规范

- 每组操作优先突出一个主要按钮，辅助按钮采用白底边框；危险按钮保留红色。
- 普通筛选只占一行，标签在输入框上方，按钮与输入框底部对齐；空间不足时将次要条件收入高级筛选，手机同样不换行。高级筛选展开后可独占下一行，保持原控件、选中值与事件。
- 表头使用浅底，正文数字等宽；悬停与勾选行使用轻微蓝色覆盖，不消除行内业务状态。
- 普通卡片不用大阴影，浮层与弹窗才使用层级阴影。
- 导航选中状态有底色和边缘指示，焦点必须可见。保持搜索、折叠、Esc 关闭和移动抽屉行为。
- 首页图标统一蓝色，文字承担模块识别；业务成功、失败和风险标记继续使用语义色。
- 手机通用主要控件至少 44 px；订单固定视口内的紧凑筛选沿用 32 px 专用布局，避免挤掉列表与统计区。尊重系统“减少动态效果”偏好。

## 四个产品工作区

1688 产品区、美客多跟卖采集、AI 原创产品和产品列表通过 `catalog-workspace.js` 复用同一套页面骨架。标题、筛选、选择栏、批量编辑和分页分别使用 `zs-catalog-*` 标记，布局放在 `console-layout.css`，控件尺寸放在 `erp-density.css`，外观放在 `design-system.css`。

- 列表内先筛选、后勾选与批量操作；“全选本页”和“查询”使用统一文案。
- 勾选商品后展示“批量编辑”，展开后占独立一行；Enter / Space 展开，Esc 关闭并返回触发器。
- 手机保留搜索、查询和高级筛选，重置等次要控件按空间移入高级筛选；移动原节点，保留值、事件和权限标记。
- 采集安装说明使用可展开帮助。AI 原创保留完整编辑卡片，业务状态、校验提示和专用字段继续由原模块负责。

`tests/test_catalog_workspace_browser.py` 使用真实模板和模拟商品，检查四种宽度下的外观一致性、勾选、键盘操作和缩放后的状态保留。

## 验收与维护

用离线真实模板检查 1440、1024、390 px：总览、订单筛选、产品列表、独立页面和登录页。表格可在自身容器横向滚动，页面不能因控件撑宽。检查多选面板、禁用按钮、键盘焦点、导航搜索无结果及移动抽屉。

运行相关现有测试，更新修改过的 CSS 资源版本以避免浏览器沿用旧缓存。重启沿用项目 `restart_workbench.sh`，完成后检查登录页、静态资源和各服务健康端点。

### 全模块筛选与二级页面

- `compact-filters.js` 统一管理紧凑筛选的计数与无障碍名称；日期和工作流组件通过 `zsRefreshFilterSummary` 刷新，避免多个组件反复覆盖展开按钮的文字。
- 查询按钮按实际字体、内边距和边框预留宽度，优先保留搜索与主查询；订单重置可以独立移入高级筛选。日期范围在字段内换行，不能撑宽页面。
- 采集详情独立页使用 `zs-standalone zs-collection-detail`，与工作台详情抽屉共享外观。长链接换行；说明表格保留自身横向滚动及键盘焦点。
- `tests/test_module_ui_consistency_browser.py` 逐页展开筛选，打开原生选择框、多选浮层、模块子视图及静态弹窗。使用离线模板和模拟商品，截图与逐项清单输出到 `artifacts/module-ui-20261016/verified`。有数据的编辑器、选择状态与详情内容继续由现有专项测试验证。
