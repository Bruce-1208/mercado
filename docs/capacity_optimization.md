# 容量优化与验证（2026-09-23）

本次针对中心服务支撑更多用户的前五项建议进行改造。保留旧 HTTP 接口、数据库结构和 Agent 队列；不通过增加 MySQL 最大连接数扩大负载。尚未进行 100 用户、1,000 店铺的生产混合负载验收。

## 行为和边界

1. **Agent 请求与写入**：Agent 1.2.4 运行任务时每 5–5.5 秒心跳，空闲默认 10–11 秒。停止指令可能比旧版晚约数秒收到。旧 Agent 协议兼容，服务端对同一会话/任务/元数据的重复心跳在 5 秒内复用结果；新会话、新任务、新版本立即持久化，取消标记每次请求仍查询。租约默认 15 分钟，未缩短失联保护。Windows/macOS 打包客户端须重新构建并安装才会减少 HTTP 请求；旧版立即受益于服务端减少写入。
2. **统一同步预算**：订单、历史订单、链接、侵权、禁限售的店铺协调任务共用 8 个位置，普通任务最多占 6 个，近期/手动订单优先。详情线程不嵌套占用店铺位置；API Client 的 JSON/二进制请求另共用 32 个在途位置，同一凭据最多 8 个，异常与重试等待均释放位置。上传视频、其他第三方客户端不在这个 API 预算内。预算属于每个进程，因此中心同步必须由唯一 worker 执行。
3. **分批及排队**：自动链接/侵权/禁限售每轮最多调度 8 家店铺，其余到期记录继续保留在数据库。手动请求与自动调度沿用同一同步入口和跨进程任务锁。侵权/禁限售忙碌时也持久化其他店铺的更新请求，避免直接丢弃。相同类型/店铺的在途协调任务串行；订单任务沿用现有忙碌返回和每日断点机制。
4. **查询与导出**：筛选后的链接总数缓存 15 秒，缓存键包括数据库、实际 SQL/参数及授权店铺集合，写入操作使用原有缓存失效入口。总数允许短暂延迟，明细仍查询实时数据。权限范围元数据缓存容量从 32 扩到 256；已存在的显式列、分页索引和翻页方式保留，不做大表在线 DDL。修复费用刷新 SQL 中未转义的 `%`，用真实 PyMySQL 参数绑定覆盖回归。
5. **后台导出**：六类导出（旧侵权、声誉、违规总览、权利人、禁限售、风险检查）可通过 `/api/exports` 创建持久化任务，每人最多 2 个排队/执行中任务，全局最多 100 个，由一个导出线程生成。相同人员/权限范围/URL 的在途请求合并。执行时重新鉴权，状态和下载核对创建者及当前权限/店铺范围；文件最多保留 24 小时。服务重启时将未完成的 running 导出标为错误，明确要求重新提交，queued 导出继续执行。旧同步导出 URL 保留以兼容旧页面。
6. **业务包检查**：文件大小、mtime、ctime 均不变时不重复读取源码计算哈希；首次及强制构建同步执行，之后的周期检查在后台完成，心跳继续返回上一个完整版本，构建失败保留旧版本。业务包仍以 SHA-256 校验下载内容。

## 分离部署

兼容的单进程入口仍为：

```sh
python -m bit.bit_interface --role server
```

中心服务器的源码部署可改用：

```sh
python -m bit.workbench_services
```

管理进程启动并监督两个子进程：

- Web：公网入口仍是 5000，数据库连接池默认 6；不启动中心定时调度。
- worker：只监听 `127.0.0.1:5001`，请求线程默认 16，数据库连接池默认 8；负责唯一调度器及有进程内状态的任务。

Web 将指定的任务启动、停止、状态和导出请求转发到 worker。使用共享工作台会话密钥对方法、路径、请求体、时间戳和原始访问 IP 签名。worker 验证本机来源与签名，再执行原有登录/权限校验；公网数据库请求不会因转发而获得 loopback 权限。业务 POST 不自动重试；店铺链接同步状态 GET 遇到连接错误时最多自动重试 3 次。worker 仍不可用时返回 503，用户应先检查任务状态。

两个子进程必须使用相同工作目录、`WORKBENCH_SECRET_KEY`/密钥文件、`BIT_RUNTIME_LOCK_DIR` 和固定 Agent 队列路径。管理进程以规范模块名导入工作台，避免同一进程重复加载两份任务状态。进程锁限制一个中心调度器；不应同时运行旧 combined 服务和新 worker。当前方案仅为一台主机上的 Web/worker 分离，不是多机多副本部署。

可调配置：

| 变量 | 默认 |
| --- | --- |
| `MERCADO_SYNC_STORE_BUDGET` | 8 |
| `MERCADO_SYNC_ORDER_RESERVE` | 2 |
| `MERCADO_SYNC_AUTO_BATCH_STORES` | 8 |
| `MERCADO_API_INFLIGHT_LIMIT` | 32 |
| `MERCADO_API_ACCOUNT_INFLIGHT_LIMIT` | 8 |
| `BIT_WORKER_PORT` | 5001 |
| `BIT_WEB_DB_CONNECTIONS` | 6 |
| `BIT_WORKER_DB_CONNECTIONS` | 8 |
| `BIT_WORKER_WSGI_THREADS` | 16 |

Cloudflare Tunnel 继续连接 5000，无需开放 5001。切换前检查中心正在运行的手工任务，等待合适窗口；Agent 的已入队任务保存在原固定 SQLite，不删除或迁移。

## 验证

```sh
python scripts/test_capacity.py
python scripts/test_capacity.py -q tests/test_console_ui_browser.py
node --check bit/static/background-exports.js
```

测试入口将导入时的核重核价存储替换为临时 SQLite，禁用自动调度，MySQL 指向不可用的本机端口，Agent 队列与运行锁使用临时目录，不向真实店铺、Agent 或生产 MySQL 写入。四组旧页面业务测试使用显式模拟身份，独立的鉴权/权限测试继续执行原鉴权代码。

新增覆盖：并发预算及异常释放、同一店铺串行、并发领取只返回一个任务、旧 Agent 写入合并与取消/重启、业务包变更与缓存、计数缓存隔离和失效竞争、真实 MySQL 参数格式化、导出合并/重启/权限变化、HTTP 转发签名和原始 IP、真实 HTTP Web→worker 会话和 Cookie、100 个 Agent 心跳的临时 HTTP 验证、浏览器排队导出下载和权限失效。

在线验收仍须包含 1,000 店铺的实际数据量、正常查询与全部后台同步周期。以上隔离测试不能作为 100 用户生产容量承诺。

## 本次回归结果

核心回归 377 项通过；浏览器及申诉交叉回归 209 项通过。测试同时覆盖原有申诉功能改动，未覆盖生产 1,000 店铺的完整混合负载。并发测试发现并修复了 SQLite 冷启动时重复设置 WAL 的锁竞争，且连接在事务上下文结束时关闭，减少连接积累。
